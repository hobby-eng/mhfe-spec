### Findings

#### AUD-010-API001 — Medium — Suite 3 emergency commands omit source and stated word-count validation

- **Category:** API
- **Severity:** medium
- **Status:** open
- **Release blocking:** true; The emergency creation path accepts input outside PCK-1 before its expensive KDF. This must be corrected before claiming these shipped emergency tools enforce the specification input contract. Coordinator makes the final release decision.
- **Affected files:** [{"file": "scripts/independent-suite3.py", "startLine": 93, "endLine": 100}, {"file": "scripts/independent-suite3.py", "startLine": 274, "endLine": 288}, {"file": "scripts/independent-suite3.py", "startLine": 508, "endLine": 509}]
- **Reproduction:** {"entrypoint": "suite3.main([\"encrypt\"])", "stdin": "abandon abandon ability\npublic audit password\npublic audit password\n", "setup": "Load the unchanged module; replace openssl_argon2id only with a recording boundary that raises ArgonBoundary before any KDF. Run python-contracts-probe.py in normal mode.", "secondCase": "suite3.main([\"decrypt\", \"13\"]) with the published zero-12 container and the same synthetic password."}
- **Expected behavior:** Reject the three-word source and the unsupported stated length before reaching Argon2.
- **Observed behavior:** Normal mode decodes abandon abandon ability to four zero bytes and reaches the Argon2 boundary once. Stated length 13 also reaches the boundary once. No Argon2 call or final encrypted output was executed.
- **Impact:** Unsupported source data enters the expensive encryption path; its four-byte source length cannot be represented by the specified recovery lengths. Unsupported stated lengths also waste a full recovery. This is not a demonstrated loss of an existing valid wallet.
- **Evidence:** ["python-contracts-normal.log", "python-contracts-normal.command.json"]
- **Recommended fix:** Validate source token counts before BIP39 bit decoding, and validate stated recovery counts against {0,12,15,18,21,24} before permutation work. Keep checksum and count rejection independent.
- **Required verification:** Boundary tests for all supported lengths and 3, 11, 13, 25 words, including the public three-word counterexample; invalid stated counts must make zero KDF calls. Verify existing published valid sources retain their bytes.

#### AUD-010-API002 — Medium — Both emergency suites pass out-of-range PIM and MEM to the KDF boundary

- **Category:** API
- **Severity:** medium
- **Status:** open
- **Release blocking:** true; The shipped emergency entrypoints do not enforce WF-2 and can attempt settings compatible implementations refuse. Final release acceptance belongs to the coordinator.
- **Affected files:** [{"file": "scripts/independent-suite3.py", "startLine": 110, "endLine": 129}, {"file": "scripts/independent-suite3.py", "startLine": 310, "endLine": 312}, {"file": "scripts/independent-suite3.py", "startLine": 502, "endLine": 509}, {"file": "scripts/independent-suite4.py", "startLine": 261, "endLine": 269}]
- **Reproduction:** {"entrypoints": ["suite3.main([\"encrypt\",\"1024\",\"0\"])", "suite3.main([\"decrypt\",\"0\",\"1024\",\"0\"])", "suite4.main([\"encrypt\",\"1024\",\"0\"])", "suite4.main([\"decrypt\",\"1024\",\"0\"])"], "inputs": "Published zero-12 / same-length-nonzero-12 phrases or containers and a synthetic public password. Repeat each with PIM 0, MEM 22.", "setup": "Recording Argon boundary raises before any cryptography operation; see python-contracts-probe.py."}
- **Expected behavior:** All eight upper-bound-invalid cases are refused locally with zero KDF calls.
- **Observed behavior:** Each of eight cases reaches the Argon boundary exactly once carrying PIM 1024 or MEM 22. The pass formula maps PIM 1024 to 12300 passes, without a suite-range check.
- **Impact:** PIM 1024 can enter a nonconforming creation/recovery computation; MEM 22 is not rejected by the script before invoking its KDF adapter. Negative values can already fail in unsigned encoding, so this finding does not claim every invalid integer is accepted.
- **Evidence:** ["python-contracts-normal.log", "python-contracts-normal.command.json"]
- **Recommended fix:** Use a shared explicit PIM/MEM validator before source permutation and before constructing a KDF. State supported memory levels and enforce a resource limit without reducing protocol parameters.
- **Required verification:** Check omitted/default 0, valid endpoints 1023/21, invalid -1/1024 and -1/22 using a recording KDF boundary; invalid values must make zero calls. Do not execute large valid endpoints merely to test validation.
