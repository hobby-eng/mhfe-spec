## Exact correspondence and limits

For a successful sequential search, the revealed transcript is N failures followed by one pass.
The Lean count N is zero-based; the ordinary number of attempts is N+1. EasyCrypt exposes the
actual outcome list. These encode the same successful sequential information, not two different
notions of trials.

Lean's WalletCount.real is tied to the actual owner queries on the same S/T tables and selected
source by stationary, finish_loop and completed_loop. survival proves the actual exhausted-prefix
probability `(1-p_U)^c`; capped_close bounds every after-cut continuation by that tail on nonempty
passing sets. Because p_U>0 there, the tail vanishes: this justifies the operational interpretation
of the unbounded law. No separate named Tendsto/uniqueness theorem is declared. When U is empty
the unbounded owner does not return; completion/fallback conventions are charged in the averaged
bound, not asserted to describe a real returned container.

Both systems preserve the actual source and table in the scored seed/pair game and the creation
refusal. Lean's transfer compares the whole count-indexed game, including arbitrary refusal
responses. EC's Rf has the same {-Gen} restriction as base Theorem5/W5. Its refusal-as-win
continuations are proof devices: setup_seed establishes the winning response's precondition,
and final adversary/events/budgets are not narrowed to that always-winning response.

Lean derives geometric-count distance through the ideal-rate denominator and averages true
passing-set moments, including S collisions, to obtain2^-120. EC uses a sharper average deviation
and an internal finite cutoff: slack2^-138 absorbs both2^-256 cutoff tails. Both final inequalities
retain exactly one2^-120 addition and the original main terms/error terms. This asserts the
stated addend, not optimality of the constant.

All six Lean deterministic/randomized endpoints and the three EC final endpoints retain their
finite alphabet, independent-prior/table, program/losslessness and hard-budget premises. In
particular, the full passphrase alphabet is finite, including queried zero-prior labels; finite
support alone is not the same premise. Budgets hold for every revealed count/strategy. Neither
an expected query budget nor arbitrary physical execution is silently substituted.

Independent randomized strategies justify duration computed from the revealed transcript and
independent randomness through a common postprocessing kernel. The duration itself need not be
unconditionally independent of secrets/functions: its permitted transcript input already has a
small table/passphrase dependence, and the statistical error pays for it. Extra dependence on
password, function entries, rejected values or passphrase/phrase lengths is excluded. Measured
wall-clock time is not automatically such a synthetic observation.

The general2^-136*n, workers and a capped search exposing attempts remain outside the final formal
endpoints. A fixed-table cutoff-law lemma is not a final capped source-game security theorem.
The general scheduling countermodel above does not apply to the actual first-pass sequential
interfaces. Restrict the new coin condition to the disclosure extension; hidden-trial uniform
selection can remain valid with weaker coins because no count is exposed.

#### 1. What the count means and how it refers to actual generation

`TrialLaws.failures` (lines 30–38) counts failures before the first pass, with mass `(1-p)^n*p`. It is zero-based. The ordinary number of attempted trials is `n+1`. For a sequential successful generation, its entire outcome sequence is `n` failures followed by one pass, so disclosure of this natural number is exactly as informative as disclosure of the number and pass/fail outcomes. There is no loss of information from this encoding for that rule.

The underlying owner program is not an abstract Bernoulli experiment unrelated to the source. `GenerationSampling.lean:206–215` defines `WalletGeneration.loop`: each supplied entropy causes an actual S query at `(entropy, passphrase)`, then an actual T query at the resulting seed, and only the first matching check returns its entropy, seed and tail. `execution_cons` at lines 217–234 exposes the exact two-query trace and recursive failed branch. No fresh T value is drawn on repeated seed queries; the fixed table preserves repeated-input consistency.

`RandomTrialLists.law` at `GenerationSampling.lean:66–67` samples a uniform finite function `Fin count → Entropy` and converts it to a list. Its product/prefix laws supply independent uniform entropy draws, including repeats. The proof does not replace rejection sampling by sampling entropy without replacement.

`WalletCompletion.passing` and `.make` at `GenerationSampling.lean:426–433` use the same fixed S/T table and q. The selected object explicitly retains the entropy as well as its derived seed/tail. `WalletCount.rate` (TrialCount lines 277–279) is exactly the cardinality of that passing set divided by the full entropy cardinality. It is not an independent proxy parameter.

On a nonempty passing set, `WalletCount.real` (lines 296–302) is defined as the product of the geometric failure count at this actual rate and `WalletCompletion.real` on that same table/q/target. This product definition alone would not establish that it is the owner's joint law. The following bridges are essential and present:

#### 2. Unbounded retry, positivity and uniqueness

There is no infinite recursive Lean owner program here: the executable owner is a finite-list oracle program. The PMF `WalletCount.real` is its completed, almost-surely-terminating law on fixed tables with U nonempty. I specifically challenged whether arbitrary stationary continuations leave this interpretation underdetermined.

The current `survival` plus `capped_close` resolve that substantive challenge. For nonempty U, `rate_pos` gives `p_U>0`, and `rate_le_one` gives `0≤1-p_U<1`. Consequently `(1-p_U)^count` tends to zero. Since the actual prefix's output is fixed as soon as a pass occurs, every possible tail behavior changes the result only on an event with that vanishing probability. Thus no different PMF can be the finite-cutoff limit on any Boolean test. This is a conventional and sufficient operational characterization of sequential unbounded rejection sampling; it does not rely only on an unproved assertion of stationary uniqueness.

The chapter does **not** declare a separate `Tendsto` theorem, an infinite-product-space sampler, or a named limit-uniqueness theorem. Its docstring at lines 548–550 and README lines 125–129 express the mathematical consequence of the finite quantitative theorems, rather than the type of a separate Lean limit theorem. A named convergence/uniqueness corollary would improve literal machine coverage and avoid recurring ambiguity, but absence of that corollary is not evidence that the final count law is false or circular.

Edge cases:

- If every entropy passes, `p_U=1`: the count is deterministically zero; the recurrence and cutoff error remain correct (`0^0=1` for cutoff zero).
- If no entropy passes, `p_U=0`: an unbounded owner does not terminate. `WalletCount.real` defines a fallback with count zero and the old arbitrary selected-value fallback. The positive-rate operational lemmas deliberately require U nonempty.
- The final security theorem does not condition on U nonempty or redraw S/T until U is nonempty. `WalletCount.close` (599–615) handles empty U by proving `gap=1` and applying universal distance ≤1. The average gap estimate includes these tables. An arbitrary fallback is therefore charged in full; it is not mistaken for a possible successful execution of the divergent owner.

#### 3. Geometric comparison and continuation

`TrialLaws.renewal` and `.renewal_real` (41–84) prove the recurrence from the explicit PMF mass. `failures` is normalized by the geometric sum, with strict positivity and `p≤1` proving the needed nonzero/finite denominators. No distribution normalization is assumed.

`fixed_point` (55–64) assumes a bounded real family with `D_i ≤ c+r D_shift(i)`, `0≤r<1`. It derives the bound from the supremum. Its application does not assume convergence, nonnegative differences, or the final inequality. Differences of test probabilities are bounded above by one, which is exactly the boundedness used.

`TrialLaws.close` (88–163) proves both directions of Boolean-test closeness by `|p-q|/q`. I checked the potentially asymmetric denominator: both recurrences use contraction factor `1-q`, where q is the *ideal* pass probability, so the desired denominator q is justified even in the reverse direction. In particular, the backward algebra uses

`(q-p)*(indicator - P_shift) + (1-q)*(Q_shift-P_shift)`.

The first factor's absolute value is bounded by `|q-p|` because both indicator and shifted probability lie in [0,1]. The reverse direction does not accidentally give `|p-q|/p` instead.

`TrialLaws.kernel` (166–215) derives contraction through the same arbitrary PMF continuation from test closeness. It uses the set of positive mass excess, bounds the accumulated excess by the assumed test distance, and justifies finite cancellation with PMF mass ≤1. The continuation may depend on the count; it is not required to ignore the observable being disclosed.

`WalletCount.ideal` (587–589) replaces only the count's pass rate by the reciprocal of the check cardinality. It retains **the same** `WalletCompletion.real table q target` as the actual law. `WalletCount.close` then lifts the geometric comparison through that selected-value continuation. There is no incorrect replacement of the table-dependent selected E by an unrelated entropy independent of S/T/Q.

#### 7. Duration and independent coins

The randomized endpoints draw `coins : PMF Strategy` outside the complete source experiment. Their law is independent of secrets, functions and owner trials; the program may then be a function of `(strategy, count)`. Therefore any disclosed duration `duration(count, strategy)` can be incorporated into the attacker's choice of program. The theorem gives the adversary at least as much information as that duration, because it indexes by the whole strategy and count. This is a sound postprocessing interpretation of the duration condition for the sequential rule.

There is no explicit clock, timer, scheduler, PBKDF2 cost model, source-code timing trace or hardware timing measurement in this chapter. The result does not prove constant-time BIP39/PBKDF2, does not establish that a real implementation's elapsed time has the required independence, and does not cover duration dependent on rejected entropies, phrase/passphrase byte lengths, secrets or function values. Independent coins cannot be used as a label for randomness correlated with such hidden data.

Recommended common wording for the specification's references to timing:

> A generation may disclose its trial outcomes and number. The bound for disclosed duration applies only when that duration is a function of those outcomes and additional coins jointly independent of the secrets, the functions and the trial values. For the sequential rule the added term is `2^-120`. This condition does not describe timings that depend on the phrase or passphrase byte lengths, as a BIP39 seed computation can.

The current README sentence at `mhfe_spec/README.md:805–806` permits elapsed time when an individual trial's duration depends neither on its value nor on the passphrase. As an isolated permission, this does not exclude dependence on other secrets or function values. It should use the full A.6 condition above. This is a documentation alignment issue under DOC-06/DOC-07, not an attack on the correctness of `TrialEnvironment.transfer`.

The shorter phrases at `DESIGN-NOTES.md:506–508` and `:3963–3965` say duration depends "only on these" (outcomes/count). Literally that is narrower than the version also allowing independent coins; it does not authorize secret-dependent timing. Adding the independent-coins wording there improves consistency and accurately states the more general permitted postprocessing. It should not be described as repairing an independently demonstrated secret-timing leak in those two sentences.

#### 10. Skeptical follow-up: independence of selection and scheduling coins

The coordinator requested a challenge of a separate reviewer's candidate after the initial source pass. I accept a concrete missing-hypothesis interpretation of the general prose, while distinguishing it from the correct sequential Lean statements.

At `DESIGN-NOTES.md:4707–4711`, the first three selection conditions require independent uniform trials, an index selected by order/outcomes and coins independent of the trial values, and almost-sure termination when U is nonempty. They do not explicitly require those **selection/scheduling** coins to be independent of P, Q or the functions. At lines 4738–4740, the stronger independence from secrets/functions is stated for coins producing the disclosed duration. That does not literally add the same condition to the earlier selection coins. The paragraph then claims the bound for a rule satisfying only the first three conditions.

Consider the following literal countermodel:

1. P is uniform on two passwords labelled 0 and 1; Q has a known singleton prior. All entropy trials are iid uniform and independent of P and the random functions.
2. Let the selection coin C be the random bit P. C is fair and independent of every trial value, of their whole sequence, and of S/T. It is not independent of P.
3. If C=0, select the first passing trial; if C=1, select the second passing trial. Select no other way. This rule uses only order, pass/fail outcomes and C, and stops almost surely on every nonempty U.
4. The selected entropy is uniform on U in both cases, even conditioned on P. Therefore the source-only selection argument itself does not reveal the problem.
5. Reveal the pass/fail outcomes as expressly permitted by the new paragraph. Their number of passes is exactly one versus two. An attacker recovers P perfectly on every terminating generation, knows the sole Q, and outputs the exact pair with no oracle queries.

The ideal expected number of trials averaged over P is `n=(3/2)*2^16`, since reaching one versus two passes at the ideal rate takes means `2^16` versus `2*2^16`. The additional term `2^-136*n=(3/2)*2^-120` is tiny. At zero query budgets, Theorem 5(b)'s main term is `p1*s1=1/2`, and its error terms are tiny. Thus the general count/outcome claim, if its explicit independence list is exhaustive, is false by a constant gap. Empty-U tables do not cure this example: recovery is exactly one conditional on U nonempty, and unconditionally at least `Pr[U nonempty]`; the stated variance bound gives `Pr[U empty]≤2^-240`.

This is not a side channel in the actual sequential algorithm and does not refute any new Lean theorem: the sequential rule has no secret-dependent selection choice, and the randomized final endpoints explicitly use an external independent PMF mixture. Nor is the witness an argument that properly defined fresh algorithm coins may depend on secrets. If "coins" is taken by convention to mean randomness jointly independent of every input, the intended claim excludes C. The issue is that the prose names only independence of trial values at precisely the place that defines its general class, whereas another clause explicitly names secrets and functions. An exact-wording audit should remove reliance on the implicit convention.

Recommended disposition: a **Medium documentation/theorem-hypothesis finding** for the general selection/outcome disclosure claim, or an explicitly identified quantification ambiguity if the report reserves "false" for the intended standard fresh-coin convention. It is not a High implementation finding, not a failed Lean proof, and should not block publication of the accurately scoped sequential Lean result. It should block an unqualified assertion that the general prose is fully correct exactly as stated until clarified.

Recommended wording: add a separate condition in A.6's **number-of-trials disclosure paragraph** requiring the selection and scheduling randomness of a rule that reveals its outcomes/count to be jointly independent of the secrets, the functions and the entire trial-value sequence; preserve the analogous condition for any additional duration randomness. State the intended conditioning explicitly if a more general conditional independence formulation is preferred. This directly excludes the witness and justifies treating the ideal outcome process and rule randomness as independent attacker coins. It need not strengthen the preceding hidden-trial selection rule: the example's P-correlated choice between the first and second pass still selects an entropy uniform on U when the outcomes/count remain hidden, so that earlier rule can legitimately have a weaker condition.

`Passphrase.ec:298`–`:310` defines each actual trial by drawing `e` uniformly

#### Exact mathematical condition and its limits

Let C be a fixed public configuration, O the revealed pass/fail transcript, H the remaining hidden
state (P, Q, all oracle tables, trial values and selected source), and D the additional time
observation. In the sequential setting, a sufficient condition is a common kernel K_C such that

`Law(D | O, H, C) = K_C(O)`.

Equivalently, sample R independently of the whole generation's hidden inputs/trials and compute
`D = f(C, O, R)` by the same f in the real and ideal games. The proof compares the joint game laws
with O; applying the same continuation cannot increase their distance. There is no requirement
that O itself be independent of H in the real game. For the sequential rule it is represented by
the number of failures N, since O consists of N failures followed by one success.

For an interactive progress/timing trace, each newly emitted value must be produced from the
revealed outcome prefix and suitable independent coins; knowing only the terminal scalar time
does not certify all intermediate scheduling observations. The formal interfaces can abstract
a transcript as a value available to the adversary, but no theorem here verifies a physical
clock, cache trace, operating-system scheduler, browser progress callback or real timing code.

For a general selection rule, its fresh selection/scheduling coins may affect both stopping and
O. They need not remain independent of O after conditioning on stopping. The sufficient causal
condition is that those coins are sampled independently of secrets, tables and trial values,
and that scheduling/selection/timing uses only permitted outcome information and public inputs.
One then couples the same coins along with the same potential trial outcomes. Do not infer a
shared postprocessing kernel of O alone if hidden scheduling coins influenced O and are later
partly disclosed, without accounting for their joint law.

This distinction is a reason to spell out independence for **all** selection/scheduling/timing
coins when explaining the general-n paragraph. A.6's first selection conditions explicitly say
only “coins independent of the trial values” (4710), whereas the timing paragraph specifies
independence of secrets/functions/trial values (4740). Under an unusually literal marginal-only
reading, using a password bit to choose the first versus the second passing trial preserves the
selected source's uniform law on U but makes the disclosed count reveal information about P;
the ideal transcript is then not independent of P. Conventional fresh “coins” and the actual
formal rule restrictions exclude this construction. It is an ambiguity to close in explanatory
wording, not a counterexample to the checked sequential endpoints or a claim that the formal
rules can read P.

Public MEM/PIM, suite and fixed platform configuration can change cost without leaking a secret
when the analysis is performed at that fixed public configuration. A public parameter that was
itself selected using a secret is different: condition the prior on its disclosure and retain the
specification's independence assumptions (DESIGN-NOTES:210–218). Q's byte length and the trial
phrase's UTF-8/word-byte lengths are functions of secret inputs, not independent noise. A.6:4759–
4761 correctly identifies such BIP39 timing as excluded. Merely adding independent noise to a
secret-dependent time does not remove its forbidden dependence. Withholding a UI timer alone
does not establish absence of an external timing observation.

The added term is an **unconditional** game probability bound over generation and random tables.
It is not a bound for every fixed unusually biased table, every fixed count, or a posterior game
conditioned on a rare count. For tables with no passing value the unbounded real loop does not
terminate; the models use completion/fallback conventions and charge that exceptional region.
The guarantee must not be presented as unconditional physical termination of every generation.
