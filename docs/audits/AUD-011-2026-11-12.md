inequality, misplaced success event or assumed security conclusion was identified under the

scoped formal result, not a claim that the entire utility or every unrestricted prose assertion

### Deniability results

#### Lemma 1: consistency

Text lines 561–569 assert both that D_Q(Y) can be read as a valid 24-word BIP39 phrase and that
E_Q(D_Q(Y))=Y. `Model.ec:149` (`invpermK`) and `Model.ec:155` (`permK`) establish the two inverse
identities for every password and every fixed choice of functions. Their proofs cancel individual
forward/inverse rounds using the XOR group laws, and then cancel the folds in opposite order.

**Verdict: exact for the permutation identity; semantic bridge for phrase validity.** The
formal source has no executable BIP39 word/checksum encoder. Reading every 256-bit entropy value
as one valid 24-word phrase is an external representation fact. Do not describe this as a
machine-checked proof of a BIP39 implementation.

#### Lemma 2: uniformity

Text lines 571–574 assert that F(Z) is uniform and independent of an independently selected
permutation F. `Model.ec:172` (`lemma2`) proves a distribution equality
`dlet dF (fun F => dmap dstate (fun z => (F,F z))) = dF * dstate`, under the assumption that every
supported F is bijective. This is the joint independence statement, not merely a pointwise uniform
marginal. The uniform-state distribution is instantiated with actual bit strings in Suite3 and
the suite-4 instances.

**Verdict: exact, and expressed more explicitly as a joint distribution equality.**

#### Lemma 3: one fixed input and at least two rounds

Text lines 576–583 concern independently random round functions. `Model.ec:613` (`lemma3`) gives
`Pr[Rounds.run(n,x)=y]=mu1 dstate y` for every fixed x,y and n≥2. `Rounds` is the independent
round-function model; round indices make its queried points distinct. `dlist_rounds` proves the
uniformity of a fixed input under independent masks, using the bijection of the first two masks

### Important qualifications, not demonstrated mathematical counterexamples

1. **Terminating adversaries.** Public security theorems are stated under module losslessness and
   budgets on every execution against every implementation of the interface, not merely against
   consistent random-function answers. The documentation explains memoization/capping for
   impossible answers. It does not present a machine-checked timeout/limit lifting to arbitrary
   partial algorithms. Preserve the qualification when claiming word-for-word equivalence to
   unrestricted prose quantifiers.
2. **BIP39 encoding.** The formalization's mathematical validity facts concern entropy states,
   abstract phrase constructors and injectivity. A claim that the actual BIP39 encoding/parser or
   the actual utility was verified would overstate this review and these files.
3. **Maximum budgets are not exact costs on every run.** G8/Match returns at the first pass, so
   its `cg<=m` does not mean it always performs m G calls. The text's `qG=m` must be read as the
   budget chosen for the comparison. At m=0 the formal algorithm still makes its one shared B
   query, within qB<=1; it makes no expensive query.
4. **No-verifier G10 optimization.** `MatchW` always calls G at every tested entropy
   (`OneContainer.ec:2523`) even when r=0 and the verifier type has one value. Thus its proved
   budget is qG<=m, rather than a specifically proved qG=0 no-verifier implementation. Removing
   that irrelevant call should preserve success, but this optimized attack is not the named
   formal program. The upper G10 theorem does support qG=0. This is an optional completeness
   improvement if publication promises the minimal cheap-query budget at ENT=256.
5. **Representation versus consistency.** `Instances.ec` proves all abstract width and packing
   axioms have models at the named sizes; that avoids contradictory type-width assumptions. It
   does not by itself verify normalized-password semantics, actual wordlists, wallet records or
   production cryptography. In particular the concrete deniability record type is unit.

#### Fixed known input and the actual win event

**Verdict:** exact within the specified ideal model. Quantification over arbitrary `x : state`

#### Oracle widths, independence and repeated queries

A.1 fixes 128-bit halves/salts, 256-bit keys and round indices 0 through 11
(`DESIGN-NOTES.md:3933–3944`). `Suite3.ec:6–35` realizes those widths with bit words and discharges

and independent answer components. Only the matching component is exposed by the A/B/H adapters
(189–201). Different tagged points cannot alias. Repeated queries return the same lazy-oracle
value; `Count` charges every call (204–210).

A.1 says, without loss of generality, the adversary repeats no query (3982). Charging all calls
does not weaken the formal upper bound for the text's no-repeat adversaries. Such adversaries
are included as a special case. The known-pair counting argument often uses the number of
distinct logged A points, which is bounded by the charged call count. It does not assume that
two different calls were fresh when they were not.

The password type and its probability distribution remain abstract finite parameters. This
agrees with the finite normalized encodings in A.1. No EasyCrypt proof here establishes actual
Argon2id memory hardness, concrete BLAKE2b/HMAC pseudorandomness or byte-level normalization.
Those are outside the ideal theorem's subject.

#### Budget and termination hypotheses

`A_bounded` (`Theorem4.ec:201–203`) requires each count to stay within the advertised budget on
every run for every permitted oracle implementation. `A_ll` (205–206) requires attacker
termination when its oracle procedures terminate. Theorem 4 explicitly assumes `0 <= kA`;
nonnegative B/H budgets are derived from a lossless bounded attacker (`ge0_budgets`, 369–383).
These are hypotheses on an arbitrary adversary, not axioms asserting security.

The text describes the attacker output after it halts. A lossless formal attacker is an explicit
technical restriction. A nonterminating computation contributes no success event; bounded
attackers can stop at their count limits and need not continue after impossible/inconsistent
oracle behavior. Nevertheless a publication claiming literal equality of every formal
hypothesis should name the termination convention rather than hide it.

### Detailed proof checks

#### K1: programming is a distribution identity, not a security assumption

The two selected H points have different indices j and j+1. Their construction uses A/B and H
only outside those two rounds. `h_loc` and `h_tpt` (`KnownPair.ec:222–233`) explicitly establish
location invariance and distinctness, including both boundary values j=0 and j=10. The partial
forward range is 0 through j−1 and the backward range is 11 down through j+2 (97–100).

`prog` replaces the two masks by the same XOR expressions as the text (218–220).
`perm_req` (196–209) proves both directions: a full encryption reaches y exactly when the masks
have those required values. `ev_split` (236–265) identifies the event that the entire programmed
function equals a chosen target function. The additional independent components of each product
answer are retained correctly, rather than accidentally programming A/B outputs.

`pr_s0` and `pr_s1` (319–365) prove the same probability for every complete target function and
container. The proof pays the 256-bit uniform-container factor against two 128-bit free masks.
The output is not merely claimed uniform; joint dependence with the functions is preserved.
K1's final equivalence includes an arbitrary play module's global result (547–564), so it is
adequate for any event subsequently observed by the bounded attacker.

#### K2/K3: finalization, Early and Cross are not conflated

`KPGame` (Delta2.ec:10–27) draws P before the attack without using it during the attack. It
initializes monitored forward/backward chains from x/y, logs only the attacker's calls and then
finalizes forward before backward. Both finalizations use the same oracle table; a query
made during the first finalization can therefore advance or spoil the other chain.

The monitor's `push` sets Early when the next defined point is already in the table
(`Chain.ec:40–55`). This includes finalization insertions, not only attack calls. The finalizations
do not increment the attacker `Count` counters. `Mon2.log` is likewise frozen after the attacker
returns. `run_inv2` plus `enc2_spec` and `dec2_spec` establish that non-early monitored chains
are complete. The auxiliary `Fwd.odd` flag is proved false; it is not an unmentioned security
assumption (`Theorem4.ec:31–48`).

Cross is exactly equality between A points of different rounds across the chains
(`Delta2.ec:436–440`). Same-round equalities are intentionally permitted. The cross potential
contains all 12*11 ordered unequal-round pairs, has initial value `132*e128` (1692–1698), and is
zeroed after Early. One fresh sample cannot define both compared points for unequal indices
(`Ep_phiX`, 1464–1497). Thus the formal bound applies to the intended event
`Cross AND NOT Early`, not to unconditional Cross.

K3's initial potential is `(24*p1*kA + 2*qB + 287)*e128 + (2*qH+12)*e256`
(`Delta2.ec:1326–1343`). Each chain initially carries 66 own-A-point pairs. The allowance for
the future forward insertions is 155*e128 + 12*e256, where 155=144+11. Hence the aggregate
constant is 66+66+144+11=287. Adding Cross's 132 in Theorem 4 produces 419. The charged
remaining budgets are doubled because each attack query may raise either chain's risk
(`budK`, 1179–1180). These coefficients agree with the prose argument's cases.

#### K4: the combinatorial count measures password work

`badj` selects the forward H point of round j and backward H point of round j+1
(`Delta2.ec:431–433`); backward indexing `3*(10-j)+2` is correct. `K4_pure` extracts prefix
segments using ordered chains and builds a list of distinct A points from their nonoverlapping
round ranges. Cross is used specifically to exclude an equality between the forward and
backward sublists. The formal count is over `undup(log)`, which is no larger than the text's
all-call count and agrees under its no-repeat convention.

The pure proof only counts the eleven H points of each chain that can appear in a Bad_j event.
This is sufficient, since forward round 11 and backward round 0 are irrelevant to Bad_j. It is
not a missing round or a dropped budget term.

#### Theorem 4: the averaging and fractional credit are preserved

`P1`/`P2` perform the exact programmed/unprogrammed comparison and `ec` proves that a win on
the programmed side implies win-or-Bad on the unprogrammed side (`Theorem4.ec:539–561`).
`ed` then moves the auxiliary path calculation after the attacker over the full eager function
(563–579). Only the subsequent bridge to monitored chains adds Early (624–661).

The formal proof uses a uniform auxiliary round and a permutation moving the bad rounds to
the first positions (`Delta2.ec:837–871`, `Theorem4.ec:725–745`). This is equivalent to the
text's expectation of `min(1,1[guess=P]+n_bad/11)`: when the attacker wins, every auxiliary
round succeeds; otherwise precisely n_bad round choices do. The proof does not demand an
eleven-step sequential attacker or assume that a partly tested chain has some actual success
credit. Fractional credit is a mathematical upper bound on weighted query counts.

`late_guess` (`Delta2.ec:898–910`) and `ftop_max` bound the weighted sum by
`T(1+kA/11)`. P and the auxiliary round are sampled after the attack in `Fin2`/`KPF`, and the
equivalence moving them later preserves all observations used in the event
(`Theorem4.ec:750–828`). K3 and Cross are charged exactly once in the final union bound.

#### K5: why the sharpened loss does not depend on m

`pairK` is about one wrong fixed candidate and one true fixed password, over a fresh complete
function, for every fixed x. The proof first encrypts x under p, then runs only the candidate's
eleven backward rounds (`TwoK`, K5.ec:95–104). During true-path evaluation no A point with the
wrong password has been queried; the real path has at most one H point at round 1. The loop
invariant proves those facts, rather than assumes them (166–192).

Each fresh A answer for the candidate can hit that one round-1 key with probability at most
`e256`, so eleven calls contribute at most eleven times e256. On the complement, the candidate's
last round-1 H point is fresh. Different round indices prevent its preceding H calls from
having used that point. The final fresh mask hits the fixed target half with probability e128
(`K5.ec:143–165`, `Collision.ec:54–59`). The proof does not need all previous candidates to
leave a fresh global table; it reasons about deterministic acceptance tests on the complete
function and applies a union bound before averaging over that function.

`coreK_e` uses a potential that sums false acceptance indicators of candidates preceding the
true password, or assigns failure at most 1 if the true password is absent. Its initial
expectation is bounded by pairK term by term. A true candidate always passes (`accK_real`,
203–208). Consequently the j-th (zero-based) candidate loses at most `j*deltaK`; translating to
the text's one-based j gives `(j-1)*deltaK`. No m-dependent loss is smuggled into deltaK.

#### Refusal and boundary cases

The formal refused game invokes its arbitrary continuation only when y=x. `TK_pr` proves this
first-attempt event has probability exactly `2^-256` (944–953), using uniform encryption with
fresh functions for any fixed x. `refusalK` gives the upper transfer (956–978). The continuation
receives p,x,y but may otherwise perform any terminating behavior. This is the text's additive
first-attempt correction, not conditioning on accepted creations or division by a refusal
probability. A lower transfer follows by complementing the play if needed; no direct two-sided
lemma is exported here.

For `m=0`, MatchK outputs the only candidate and performs one shared B query, zero A/H calls.
Its success is the candidate's actual mass and the top specialization gives p1. Integer and
noninteger fractional-top arguments are handled separately. For large m with `m*deltaK>1`,
the lower bound may be negative and therefore uninformative, but remains valid; it is not an
implicit assumption that the loss is small. For m beyond the finite password universe, a list
of m+1 distinct candidates cannot exist. Public top/bracket lemmas state the cardinality premise;
a saturated formulation can use all passwords with no additional tests.

### Detailed semantic checks

#### Model, interfaces and information exposed

`Passphrase.ec:28-35` constructs separate `PROM.FullRO` instances for S, T and Omega. S accepts a
256-bit state and a normalized abstract passphrase and returns 512 bits. T returns a 16-bit prefix
and 240-bit suffix. Omega returns lambda bits. No G oracle enters the W experiment. The adversary
receives exactly `(y, om)` in `AdvP.guess`, and returns a seed and password/passphrase pair.

`Setup0P` initializes the function tables, samples P and Q separately, runs the rule at Q, obtains
the selected entropy, computes its seed, encrypts the entropy and publishes its Omega image.
`GamePR` refuses precisely when Y=E. The `Rf` continuation is not permitted to mutate `Gen` and
is required to terminate; this makes the event read the intended original secrets even after an
abstract refusal continuation. This is a stated modeling hypothesis, not executable re-encryption
or setting-change code.

The abstract password and passphrase distributions refer to normalized values. The formalization
does not implement Unicode normalization or the concrete PBKDF2 input serialization; A.6 explicitly
abstracts those computations to S, relying on the injective phrase encoding.

#### Covered rules and the no-passing-value case

The rule gets only `TRIALS.trial():bool`, returns an index and cannot read trial values or oracle
tables. `Rl_pass` quantifies over every admissible trial source and requires any returned index to
point to a recorded pass. `Rl_ll` requires almost-sure termination for an invariant trial source
with positive constant passing probability. `SeqU_pass` and `SeqU_ll` establish those properties for
the actual unbounded first-success rule.

The selection proof samples S and T eagerly, splits each trial into an outcome and a conditional
value (`trial_split:353-363`), postpones values through a lazy oracle and moves the outcome-only
selection past the continuation. `fr_cov:688-710` identifies the result with a uniform passing value
on the event that its passing mass is positive. At mass zero the covered rule cannot return a valid
pass; the experiment has missing subprobability mass. Thus the proof does not assume away empty U
or assume unconditional termination of generation.

`selection_eq` compares an arbitrary covered rule with `SeqU` exactly. `selection_bound` compares it
with internal `Seq`, which stops after 2^80 trials and uses its last trial even if that trial failed.
That internal device is not the user-facing generation algorithm. The comparison costs at most
2^-256 and the slack in `deltacut_le` pays for its use in final bounds.

#### Generation distance and W5's late query

`deltagen(kS,qT) = 2^18*(kS+1)/2^256 + 2^18*qT/2^512` exactly matches SPEC 4735.
The cut-rule proof uses `Kc = (1+kS)/2^256 + (1+qT)/2^512` and
`deltacut = 2*(2^16*Kc+2^-256)`. `deltacut_le` proves
`deltacut+2*2^-256 <= deltagen`, sufficient for rule/refusal transfers.

W2's `ADVJ` interface has a run followed by a judge that can read secrets, A/B/H and Omega but
cannot issue S or T queries. This makes its distance a statement about the adversary's bounded
view and the stated joint data, not a statement about the entire unqueried S/T tables.

For W5, `J5.run` invokes only A and records its output. `J5.judge` checks that output against
`(E,Q)` without an S query. `gen5` therefore applies the generation transfer with A's original kS.
Only after that transfer does `AW5` append `O.s(g.1,g.2)`, ensuring the recorded guess belongs to
the S-query log and charging kS+1 in `AW5_bounded`, `theta_bad` and epsC. The final W5 formula uses
`deltagen kS qT` and `epsC ... (kS+1) ...`, exactly the text's distinction. This was verified by
following the wrapper, judge, transfer and final assembly, not by comparing the final formula alone.

#### Collision and pair assignment

`coll` requires another password's fully logged chain to complete no later than P's fully logged
chain and invert to the same state. The completion-time comparison is represented by first logged
moments (`bnof`) and their maximum (`taub`). `uof` sorts completed candidate passwords by that
time and ranked-password index; `Zset` assigns each S query through that function and deduplicates
the results. `Zset_props` and `Zset_mass` prove both cardinality bounds. `Zset_ext` proves that
finalization extending the table does not change Z; the subsequent delayed P,Q draw therefore
establishes independence needed by W1.

The W4 potential separates earlier completed inversion collisions (`col1`) from equal final keys
at different A points (`col2`). The final probability statement requires no Early and a logged
last chain point, matching not-N. Its bound has kA multiplying both 2^-128 and 2^-256, with no
unjustified p1/s1 improvement.

#### W7 attack and all three modes

The attack caches the last round's B answer once, then makes twelve A/H calls and eleven further B
calls per candidate password. It computes S for each candidate pair and stops at the first pass.
Mode 0 calls Omega only; mode 1 calls T only; mode 2 calls T then Omega only on T success.

The seed lower bound charges only false acceptance with a seed different from `seed*`. An
unprogrammed S answer equal to `seed*` wins that game, so there is no 2^-512 pair-loss term in the
seed rank sum. The pair proof charges both accidental seed equality and collisions between inverted
entropies of different passwords. Both differences appear in actual separate potentials and final
statements.

The source proves all orderings of distinct pairs, not just decreasing probability order. The
text's specified order is a valid specialization. `W7_top2` adds the text's ranked password list,
candidate mass `top2(m,n)` and at-most-n premise. It explicitly requires m not to exceed the finite
password cardinality, since the attack must have m distinct passwords.

### Exactness limits and recommended follow-up

#### Finite passphrase restriction

Evidence: `Passphrase.ec:10-13,48-70` clones `FinType` for all passphrases and eagerly samples S on
its whole finite input domain. SPEC 4627-4649 does not bound passphrase length or support and uses
a countable ranked list. `ASSUMPTIONS.md` explicitly acknowledges the difference. A finite-support
or finite-domain theorem is not literally the theorem for every countable distribution. No
countable-limit extension is present in the inspected W sources.

Recommendation: either formally extend the result to the text's domain or explicitly restrict the
published correspondence claim and annotate the text's formalized instance. Do not silently change
the normative passphrase input contract merely to fit the current formalization.

#### Exact uniform top2 identity is not a proved equality here

SPEC 4741-4743 states an equality containing `min(m,N1)`. `top2_uniform` proves only
`top2(m,n) <= min(n,m*N2)/(N1*N2)` and assumes uniformity on the entire finite password/passphrase
types. This weaker inequality is sufficient for the subsequent announced seed upper bound, and it
remains sound when m exceeds N1, but it does not assert the exact saturation identity or directly
parameterize uniform finite supports inside larger domains.

Search scope: all `top2`, `uniform`, `ceil` and ranked-mass declarations in Passphrase/Theorem5/W7;
final statements and the identity proof for the separate known-passphrase case were inspected.
No exact general uniform identity was found.

Recommendation: add the equality with `min(m,N1)` and a finite-support version, or state clearly that
only the upper-bound reading is machine checked. This is a formal-coverage observation, not a
counterexample to the stated identity.

#### One-cost-budget expectation is represented by a constant envelope

SPEC 4773-4779 states a success bound involving
`Exp_Theta2[top2(|C'|,|Q_S|)]`. `theorem5_cost` takes an arbitrary constant T that bounds top2 for
every pair of counts satisfying the cost constraint. That proves a useful, generally coarser bound;
`theorem5_cost_uniform` proves the text's final uniform-secret cost inequality exactly. DESIGN
254-259 explicitly documents this choice. The exact expected-value expression is not a formal
theorem in the inspected sources.

Recommendation: expose the expected-value result if every rigorous sentence is to have literal
formal coverage, or describe the present constant-envelope scope. The ehoare construction and
delayed secret sampling already establish the main ingredients; do not call the two formulations
identical without an argument.

#### Capped generation with failure is a mathematical corollary, not an encoded game

SPEC 4722-4724 says that a rule that reports failure after any stated number of trials inherits all
Theorem 5 bounds. The only bounded rule in the inspected sources is internal `Seq`, which returns
its last trial and does not report failure. It cannot stand in for the documented failure rule.
`RULE` returns an index, and `Rl_pass` requires a pass on every returning path, so a failure result
is not represented by that interface. No explicit dominance theorem for a capped failure game was
found in Selection/Theorem5/Passphrase.

The textual argument is valid for unconditional success probability: couple identical trials,
and count failure as no win. It does not assert the same bound conditional on successful creation.
Recommendation: add an optional-result failure game and dominance lemma if this exact statement
must also be machine checked, and state the unconditional interpretation explicitly in publication
instructions. This is not evidence of an incorrect T5 bound.

#### Termination hypotheses

The final adversary bounds assume losslessness whenever the supplied oracles are lossless; the
text says the adversary outputs when it halts. The notes propose capping inconsistent answers and
termination; that is a modeling explanation rather than a formal theorem extending every result
to arbitrary subprobabilistic adversaries. The report should retain this assumption. In particular,
an argument extending upper bounds to nonterminating adversaries must not be used to claim lower
attack bounds for arbitrary adversaries; W7 instead proves its concrete attack terminates.
