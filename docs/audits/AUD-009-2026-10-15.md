### Findings

#### AUD-009-FUN001 — Medium — Grouped multiplication is converted into a postfix star

- **Category/status:** FUN; open; release blocking: no.
- **Affected:** `scripts/pdf/ascii-math.mjs:179`, `scripts/pdf/ascii-math.mjs:188`, `scripts/pdf/test.mjs:51`.
- **Reproduction:** Run parser-probes.mjs through the production Markdown entry point with g(x) = (x + alpha^1)*(x + alpha^k).
- **Expected:** Both factors remain multiplied, as with the spaced-star control.
- **Observed:** The first factor receives ^{*}; no multiplication operator remains. The existing positive fixture accepts this incorrect conversion.
- **Impact:** A supported mathematical input silently changes meaning. Current normative generator equations use explicit LaTeX and were not found affected by this case.
- **Recommended fix:** Disambiguate postfix stars from multiplication using the operand type/context and add independent LaTeX/MathML expected results.
- **Required verification:** Unspaced grouped products and numeric products must preserve multiplication; postfix-star identifiers must retain their documented meaning. Rebuild both PDFs and compare inventories.

#### AUD-009-FUN002 — Low — Quoted ASCII mathematics loses a literal tilde

- **Category/status:** FUN; open; release blocking: no.
- **Affected:** `scripts/pdf/ascii-math.mjs:238`, `docs/PDF-BUILD.md:115`.
- **Reproduction:** Compare rendered MathML for quoted a~b and quoted a b, excluding source annotations, with parser-probes.mjs.
- **Expected:** Quoted characters remain distinct or unsupported characters are rejected explicitly.
- **Observed:** Both quoted inputs render identically because the unescaped tilde becomes a TeX space.
- **Impact:** The documented quoted-character preservation contract is violated. No affected quoted tilde occurs in the current source inventory.
- **Recommended fix:** Escape or reject all TeX-special characters in literal text according to their rendering context.
- **Required verification:** A literal tilde must remain distinguishable from a space; retain controls for percent, underscore, braces, backslash and caret.

#### AUD-009-FUN003 — Low — Script arguments bypass delimiter and ambiguity validation

- **Category/status:** FUN; open; release blocking: no.
- **Affected:** `scripts/pdf/ascii-math.mjs:139`, `scripts/pdf/ascii-math.mjs:142`.
- **Reproduction:** Run parser-probes.mjs for x^), x_], R^(1)_0 and the rejected control R_0^(1).
- **Expected:** Malformed closing delimiters are refused; the documented superscript ambiguity rule does not depend on script order.
- **Observed:** Unmatched closing delimiters are accepted as arguments. R^(1)_0 is accepted with removed parentheses while the reversed script order is refused.
- **Impact:** The fail-closed notation contract has uncovered paths. No such malformed expression was found in the published source inventory.
- **Recommended fix:** Validate script-argument token kinds and perform cross-script ambiguity checks after collecting the complete scripts.
- **Required verification:** All malformed controls must fail; explicit labels R_0^{(1)}, ordinary powers, indices and valid nested groups must still work.

#### AUD-009-UI001 — Low — Algorithm-name hyphens render as mathematical minus operators

#### AUD-009-DOC002 — Low — Absolute independence summaries omit fixed-point refusal

- **Category/status:** DOC; open; release blocking: no.
- **Affected:** `docs/DESIGN-NOTES.md:273`, `docs/DESIGN-NOTES.md:983`, `docs/DESIGN-NOTES.md:1022`.
- **Reproduction:** For an accepted container Y, consider a password candidate p for which D_p(Y) = Y. The creation refusal excludes that candidate.
- **Expected:** Exact independence is attributed to the unwrapped permutation experiment; operational refusals are separately qualified.
- **Observed:** Several summaries call the container fully independent of the password without that qualification, although Theorem 1 omits refusal and Theorem 2/Remark G9 account for it.
- **Impact:** The statements are literally too strong in the operational experiment. This does not refute the theorem bounds; the ideal-model exceptional probability has scale 2^-256 or 2^-ENT.
- **Recommended fix:** Distinguish exact core-permutation uniformity from the operational creation procedure and link the existing refusal accounting.
- **Required verification:** Check all independence summaries against their exact experiment and preserve the correct suite-dependent exceptional term.

#### AUD-009-DOC003 — Low — Deniability experiments lack termination or abort semantics

- **Category/status:** DOC; open; release blocking: no.
- **Affected:** `docs/DESIGN-NOTES.md:517`, `docs/DESIGN-NOTES.md:566`, `docs/DESIGN-NOTES.md:580`, `docs/DESIGN-NOTES.md:613`.
- **Reproduction:** Choose the permitted password distribution Pr[P=a] = 1. Drawing Q again while Q=P never produces a disclosure. Rare creation-redraw failures need totalization too.
- **Expected:** The experiments define outcomes for all allowed distributions, or explicitly assume sufficient termination and define failure/abort.
- **Observed:** The password domain permits a point mass and the experiment has an unbounded redraw loop, without specifying the result on nontermination.
- **Impact:** Theorem 2 advantage is undefined for this admitted edge case until the game is completed. A trivial right-hand bound at p1=1 does not define a missing experiment. No counterexample for terminating experiments or practical cipher attack was found.
- **Recommended fix:** Specify termination hypotheses and explicit abort/failure semantics, then state how the existing coupling terms account for those cases.
- **Required verification:** Check singleton and multi-password distributions, rare all-refused creation cases, and the revised coupling without silently conditioning away failure.

#### AUD-009-DOC004 — Low — Repair-card sequencing wording differs from the implementation

- **Category/status:** DOC; open; release blocking: no.
- **Affected:** `README.md:802`, `../mhfe/src/operation.rs:266`.
- **Reproduction:** Inspect Encryption::run: repair parity is computed before check_new_container; Sealed is returned only after that check succeeds. Latest inspected `operation.rs` SHA-256: `7eade1206d24691b15f3ef7985e2c4be8678a0fac17be3cfc6f13d777ed20091`.
- **Expected:** The description of computation order agrees with implementation, or clearly states that it is the release of the card that waits for verification.
- **Observed:** The specification says the card is computed after the creation check; the implementation precomputes its parity internally and withholds it until verification.
- **Impact:** This is a limited sequencing-description mismatch. No early repair-word release, incorrect card bytes or bypass of the creation gate was established.
- **Recommended fix:** Settle the intended contract and reconcile the wording or internal sequence without weakening the output gate.
- **Required verification:** Keep a failing-creation test showing no card is released and a successful-creation test showing identical parity. Bind implementation checks to exact file hashes.
