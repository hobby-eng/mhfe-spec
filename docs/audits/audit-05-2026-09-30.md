### Findings

#### AUD-004-DOC001 — Low — Password exclusions still do not guarantee universal interface input

- **Category:** DOC.
- **Severity:** low.
- **Status:** verified in the authorized addendum; open at the original baseline.
- **Release blocking:** false. A bounded explanatory defect, not a demonstrated cipher or runtime failure.
- **Affected files and builds:** README.md:209-220; explanation at lines 214-216; document only.
- **Prior disposition:** Regression of the original finding; its immutable ID is retained.
- **Reproduction:** Read the current predicate using the synthetic scalar sequence U+0061, U+200B, U+0062. U+200B is assigned, is not Cc, U+2028 or U+2029, and has no decomposition. The sequence is NFKD-stable and encodes to 61 e2 80 8b 62, within the length limit. This is reasoning from Unicode data, not an executed normalization or interface test.
- **Expected behavior:** The rationale describes exactly what the rejection predicate guarantees and does not promise universal input or display support.
- **Observed behavior:** Lines 214-216 claim that every interface accepts the allowed text as typed or pasted and needs no special way to enter invisible characters, although allowed inputs still include invisible format characters and Private Use characters.
- **Impact:** Readers may confuse protocol validity with input-control capability or remove legal characters. No particular GUI or CLI failure was demonstrated. The predicate itself is coherent; the defect is the universal explanation.
- **Recommended fix:** Replace the universal claim with the narrower explanation that excluding controls and line separators avoids common line-ending and input-control problems. State that other legal Unicode characters can still require suitable input and display support. Do not add further character exclusions as an editorial fix.
- **Required verification:** Read the final paragraph against the accepted character classes and the U+200B counterexample; preserve no-trimming and no-transformation requirements. This correction needs no Argon2 calculation.
- **Evidence:** Current README permits assigned Cf characters but promises ordinary input in every interface without special entry for invisible characters. Unicode 17 classifies U+200B ZERO WIDTH SPACE as Cf, with no decomposition mapping and no visible glyph. Local only: AUD-005-evidence/protocol-review.md and editorial-review.md.

#### AUD-005-DOC001 — Low — The manual-recovery explanation overlooks the automatic ambiguous branch

- **Category:** DOC.
- **Severity:** low.
- **Status:** verified in the authorized addendum; open at the original baseline.
- **Release blocking:** false. The normative branches are already explicit; the explanatory sentence is too broad.
- **Affected files and builds:** README.md:317-319, compared with README.md:306-312; document only.
- **Reproduction:** Compare the specified automatic branches: zero short matches yields the 24-word interpretation, one short match selects the short candidate, and several short matches also expose the 24-word interpretation. The unqualified only-way sentence conflicts with the last branch. No search for a concrete rare state was performed or needed for this textual comparison.
- **Expected behavior:** The explanatory paragraph accurately describes all three normative automatic branches.
- **Observed behavior:** The sentence applies to every genuine 24-word source matching a short layout, although manual selection is needed to obtain the 24-word interpretation only when automatic detection selects exactly one short layout.
- **Impact:** A reader may misunderstand when manual mode is necessary. The required manual option and the normative multiple-match behavior remain correct. No incorrect implementation output was demonstrated.
- **Recommended fix:** Use: Manual selection is necessary when automatic detection reports exactly one matching short layout for a genuine 24-word source. A random 24-word source matches at least one short layout with probability about 2^-32. Preserve the existing recovery branches.
- **Required verification:** Compare the edited explanation with the zero-, one- and several-match branches and the mandatory unverified label for 24-word results. No vector computation is required.
- **Evidence:** The several-match branch requires showing the unverified 24-word interpretation together with all short candidates. The following paragraph calls manual selection the only way to recover a genuine 24-word source matching a short layout. Local only: AUD-005-evidence/editorial-review.md.

The Unicode counterexample follows from [UnicodeData.txt for Unicode 17](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt), the default decomposition mapping in [UAX #44 revision 36](https://www.unicode.org/reports/tr44/tr44-36.html#Decomposition_Mappings), and the invisible-glyph description in [Unicode 17, Chapter 6, section 6.2.3](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-6/).

### Informational observations and recommendations

**Retain the existing suite immutability rule.** README.md:197-200 already requires a new identifier for incompatible changes to the suite definition. The control-character change is an owner-approved edit made while suite 3 is still an unreleased experimental draft. No new suite identifier or additional freeze-policy paragraph is recommended here. An initial compatibility candidate was rejected during consolidation because the evidence did not establish a violated published compatibility boundary, an incompatible deployed peer or an affected issued container.

**Add a compact recovery decision table.** A small table for manual short, manual 24, and automatic zero/one/several matches would make the already specified branches easier to implement. Distinguish verifier consistency, ambiguity and external wallet-identity confirmation. This is an editorial aid, not a new algorithm or another finding.

**Keep the final-word idea explicitly bounded.** The new DESIGN-NOTES.md:460-465 paragraph is acceptable in its research context: it excludes suite 3 and verifies neither the password nor the other 23 words. Optional wording such as comparison of the 11-bit final-word index is more precise than an 11-bit check of the plate. A matching label is not a unique wallet identity and is not authentication.

**Prioritize independent analysis before changing primitives.** No document-only evidence found here justifies changing the twelve rounds, domain strings, current packing or KDF mapping. The useful next technical work remains construction-specific cryptanalysis with explicit oracle/work budgets, and measured attacker-cost calibration. These are research and measurement tasks, not claims completed by this audit.

**Treat authentication as a separate future format.** The full 256-bit representation cannot add a self-contained authentication tag while losslessly representing arbitrary 256-bit source entropy. Any authenticated/self-describing alternative needs additional storage or a restricted input domain and explicit format selection. The current no-authentication limitation is disclosed, not a newly discovered defect.

**Preserve the present reading structure.** Keep the developed Rationale in README and the detailed analysis in Part I, with Part II labelled historical. The sequence and current/historical boundary work. Availability of a public corpus must remain distinct from complete independent conformance; the ongoing external vector job is not audit evidence here.
