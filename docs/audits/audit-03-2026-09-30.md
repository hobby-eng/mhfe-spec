## Summary

The notation, formulas and diagrams of the specification are correct. A harness written for this
audit from the README text alone reproduced every salt, Argon2id output mapping, mask, state,
container word and recovery result of all 17 positive suite 3 vectors and all 9 suite 2 vectors,
and four real Argon2id calls through OpenSSL confirmed the memory and pass formulas for PIM 1,
memory level 1 and suite 2. All 38 stated numbers were recomputed and agree. The BIP 3 preamble,
all 43 relative links and anchors, the reference list and the BIP39 prefix claims check out.

Six low-severity documentation findings were recorded, none of them in a byte-level definition:
an ambiguous word in the password rule, a SHOULD/MUST mismatch around the container self-check,
an overstated "salts are public" statement, an undefined symbol, a wrong bound in the supplement
and a list-nesting error in the changelog. Three informational observations concern citations and
the supplement's Part II.

### Findings

#### AUD-003-DOC001 — Low — Password rule leaves noncharacters and Private Use open to divergent readings

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.
- **Affected files:** `README.md`, "Password encoding" (line 191) and "Test Vectors" (lines
  527-531).
- **Reproduction:** Compare "normalization MUST fail if `P` contains a code point unassigned in
  Unicode 17.0.0" with UAX #15 revision 57, section 12.1, and with the Unicode glossary.
- **Expected behavior:** One reading. NPSS fails on `General_Category=Unassigned` (`Cn`), which
  includes the 66 noncharacters, and accepts Private Use (`Co`).
- **Observed behavior:** The README paraphrases the rule as "unassigned". In the Unicode glossary an
  unassigned code point is a reserved one, which excludes noncharacters, so a reader of the README
  alone may accept U+FDD0. Conversely, the common Rust helper
  `unicode_normalization::char::is_public_assigned` rejects Private Use; the reference
  implementation needed an explicit exception to accept it. The vector requirements list "an
  unassigned code point" but neither a noncharacter nor a Private Use character.
- **Impact:** Two conforming-looking implementations could disagree on whether a password is
  valid, and a container made with one could not be recovered with the other. Such passwords are
  rare in practice.
- **Recommended fix:** Write the condition as NPSS does: "if `P` contains a code point with
  `General_Category=Unassigned` (`Cn`) in Unicode 17.0.0; this includes noncharacters, while
  Private Use characters are assigned and accepted". Add a noncharacter and a Private Use case to
  the required vectors.
- **Required verification:** Reread against UAX #15 section 12.1; the suite 3 vector set contains
  both cases.

#### AUD-003-DOC002 — Low — Container self-check is SHOULD, but programmatic release requires it to pass

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.
- **Affected files:** `README.md`, "Creating a container", step 5 and the paragraph after it
  (lines 254-264).
- **Reproduction:** Read step 5 ("This SHOULD be done") and "A result passed to another program
  instead of a person MUST NOT be released before the check has passed."
- **Expected behavior:** Consistent normative strength.
- **Observed behavior:** An implementation that skips the SHOULD-level check can never satisfy the
  MUST, so for programs the check is mandatory in effect while the step says it is optional.
- **Impact:** Implementers may disagree on whether the check is required; the changelog describes
  it as an implementation requirement.
- **Recommended fix:** Make step 5 a MUST (the reference implementation always performs it), or
  limit the release rule to implementations that perform the check. The first matches the
  project's intent.
- **Required verification:** Reread the section; `CHANGELOG.md` states the same strength.

#### AUD-003-DOC003 — Low — Intermediate round salts are described as public

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.
- **Affected files:** `README.md`, Rationale, "Why BLAKE2b for salts…" (line 385: "The salt is
  computed from public data"); `docs/DESIGN-NOTES.md`, Part II heading "State-derived salts are
  public" and "It is also not secret" (lines 654-660); "Application requirements", "Sensitive
  memory" (line 351).
- **Reproduction:** Follow the inverse diagram. Only `S_11` is computable from the container
  (`R_11 = L_12`), and `S_0` from a known original. Every other `S_i` depends on `R_i`, which the
  ciphertext-only argument (supplement lines 116-122) treats as hidden behind the masks.
- **Expected behavior:** The text says which salts are derivable from public data, and lists
  intermediate salts and masks among the sensitive values.
- **Observed behavior:** The README calls salt input "public data" without qualification, the
  supplement calls state-derived salts "not secret", and the sensitive-memory list names entropy,
  states, password and Argon2id outputs but not salts or masks.
- **Impact:** An implementer could log or export intermediate salts as harmless. With one leaked
  intermediate salt, a guess can be filtered with a single Argon2id call (external AUD-002-SEC001
  demonstrates this with `S_10`). No implementation path leaking them is known.
- **Recommended fix:** README: "The salt is computed without a key from the half of the state that
  the round leaves unchanged. Only the first salt of a recovery can be computed from the container,
  and the first salt of an encryption from the original; the other salts depend on the password and
  are as sensitive as the states." Add salts and masks to "Sensitive memory" and state that
  implementations MUST NOT log or export intermediate states, salts, keys or masks outside test
  vectors built from public data. Retitle the Part II heading.
- **Required verification:** Reread both documents; the vector files keep their warning that they
  contain round keys by design.
- **Related findings:** external AUD-002-SEC001 (same root cause; see below).

#### AUD-003-DOC004 — Low — Undefined symbol `N` in "a discount of `1/N`"

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.
- **Affected files:** `README.md` line 380; `docs/DESIGN-NOTES.md` lines 167 and 362.
- **Reproduction:** Search for `N` in the symbol table and the surrounding text.
- **Expected behavior:** Every symbol is defined; the symbol table has none for the round count.
- **Observed behavior:** `N` appears only in "a discount of `1/N`"; nearby text uses `N1` and `N2`
  for counts of passwords and passphrases.
- **Impact:** Minor confusion with `N1`, `N2`.
- **Recommended fix:** "skips one of the twelve rounds, a discount of one twelfth" (and the same in
  the supplement), or define `N` as the number of rounds.
- **Required verification:** Reread.

#### AUD-003-DOC005 — Low — Supplement bound "never more than sixteen" contradicts its own formula

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.
- **Affected files:** `docs/DESIGN-NOTES.md` line 353.
- **Reproduction:** Evaluate `(k + 2) / 2` at `k = 31`, the top of suite 2's range.
- **Expected behavior:** 16.5.
- **Observed behavior:** "never more than sixteen with a range of `0..31`".
- **Impact:** A wrong bound in non-normative text.
- **Recommended fix:** "at most about sixteen" or "at most 16.5".
- **Required verification:** `numbers.py` prints the value.

#### AUD-003-DOC006 — Low — Changelog 0.3.1 entry nests two independent changes as sub-items

- **Category:** DOC. **Severity:** low. **Status:** open. **Release blocking:** false.

### Assessment and limitations

The specification defines suite 3 precisely enough to implement: an implementation written from
the README text alone matched every value of every published and fixture vector. The findings are
wording and consistency defects; none changes the byte format, and none requires a new suite.

Limitations: the Argon2id outputs of the vectors were taken as given except for four recomputed
calls; the implementation's own independent checker had already recomputed all 17 suite 3 vectors
with OpenSSL (see the specification's Test Vectors section). Python's Unicode tables are version
16.0.0, so the NFKD comparison covers only the characters in the vectors. The security arguments
were checked for internal consistency, not proved. This is not an independent cryptographic
review.

### Reassessment of AUD-002-DOC001

This record did not agree with AUD-002-DOC001 ("two identical containers reveal that they hold the
same phrase"), arguing from probability. That assessment is revised: the finding is agreed. A
counterexample needs no search: the packed state `X = E || Trunc_128(SHA-256(E))` of a 12-word
source is also valid entropy of a 24-word source, and the same permutation maps both to the same
container although the phrases differ (`addendum-checks-rerun.log`, part 3). The Security
Considerations now say that identical containers under the same suite, password and settings imply
identical packed states, which for independently chosen phrases means the same phrase, and that
they do not fix the original length. The other AUD-002 dispositions stand: SEC001 is covered by the
DOC003 fix; FUN001 is an implementation finding, fixed in the implementation repository's working
tree; API001 was resolved by the owner's decision to forbid line feeds and carriage returns in
suite 3 passwords.

### Further review of the text

A later review of the edited text, delivered to the owner in chat and not retained here, raised
statements that the fixes above had not covered. They were corrected in the same commit: the 2 GiB
browser limit is attributed to the reference C code rather than to WebAssembly; recovery and
creation times are stated separately; leaked intermediate salts enable filters of `11 - i` calls
from the container, with no claim of a lower bound; the secret-PIM effect is a calculation under
explicit assumptions and no longer a bit count in the specification; suite 2 is defined by the
archived v0.3.0 release; Conjecture 1 says what counts as a password test for short and 24-word
sources; the cost model's memory statements are limited to its full-memory assumption; statements
about alternative structures and cheaper cycle walks are limited to the variants considered; the
reverse check is described as unable to catch a mistake shared by both directions; and applications
are asked to warn at creation when the packed state also passes the verifier of another length.
