Audit: `docs/audits/AUD-011-2026-11-12.md` of the specification repository, on the sources of
2026-11-12 before this remediation (their hashes are in the report). The audit found no wrong bound

Remediation by the author of the proofs on 2026-11-12 (UTC). Every finding below is **fixed and not
yet verified by the auditor**. The package is not under version control, so the fix is bound to the
SHA-256 values at the end, not to a commit.

## Findings

### AUD-011-BLD001: the documented loop returned success after a failed compilation

- Confirmed: with a compiler that returns 7, the README's loop printed `FAILED` and ended with
  status 0.
- Fix: `check.sh` replaces the loop. It compiles every file of `src/` as the main input, in strict
  mode, stops at the first failure with status 1 and names the file.
- Checked: `check-selftest.sh`, case 1 (a failing compiler gives status 1, one `FAILED` line and no
  later file); the run on the 18 sources (below).

### AUD-011-BLD002: the recipe accepted an existing cache without checking

- Confirmed in EasyCrypt's source (`ec.ml`: an up-to-date `.eco` ends the run with status 0 before
  any proof is checked; `-no-eco` only prevents writing one; `ecEco.ml`: a cache is up to date when
  the digests of the file and of its requirements match, whatever check wrote it).
- Fix: `check.sh` does not start when `src/` holds a `*.eco` file (status 2; it lists the files and
  deletes nothing), and fails if the run wrote one. It also refuses a source that holds `admit` or a
  weak-check pragma. The README says why.
- Checked: `check-selftest.sh`, cases 2 to 4 (a false theorem with a cache from a weak check is
  refused with status 2; the same theorem without the cache fails with status 1; a true theorem
  passes).

### AUD-011-DOC001: the coverage claim hid statements that are weaker than the text

- Fix by wording: the README no longer says that every sentence is formalized; its section "Where
  the formal statements differ from the text" lists what is narrower (finite passphrases, halting
  adversaries, the one-cost-budget term), what is read through an unchecked interpretation (phrases
  and BIP39, budgets on every run, batches of Corollary G7, inequality (2), wallet records) and what
  has no formal statement. `INDEX.md` labels the rows concerned. The lemma count is gone.
- Fix by proof, for two rows of the audit's table:
  - Uniform secrets: `top2_uniform_eq` states the text's equality
    `top2(m, n) = min(n, min(m, N1)·N2)/(N1·N2)`; before, only an upper bound was stated.
  - A generation that stops at a limit and reports a failure: `SeqF` and `GameF` (Selection.ec) model
    it, with no adversary run after a failure; `capped_up` bounds every event of `GameF` by the same
    event with the cut rule plus `2·2^-256`, for every limit; `theorem5_seed_capped` and
    `theorem5_pair_capped` (Theorem5.ec) state parts (a) and (b) of Theorem 5 with the text's bounds.
    This is the unconditional form the audit describes: a failure counts as no win. No bound
    conditioned on a successful generation is claimed.
- Not fixed, and listed as narrower in the README: the one-cost-budget bound keeps a term valid on
  every run where the text writes an expectation; passphrases stay finite; adversaries halt.

### AUD-011-DOC002: "independently" suggested blind independence of the statements

- Fix: the README says that the Lean development is separate, in another proof system, and that its
  statements had been read before this development was written.
- Not changed, because they were under the auditor's review at the time: `LEAN-COMPARISON.md` and the
  README of the Lean development.
