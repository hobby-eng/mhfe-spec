## Findings

### AUD-012-FUN001: the deniability game fixed the real wallet's record before the decoy

- Confirmed. `Theorem2.oldKernel` and `Theorem2.preparedOnce` (`DeniabilityGames.lean`) draw the
  record from `realRecords : Password → Entropy → Tables → PMF Record` before the decoy password
  and the disclosed record are drawn, so the record cannot depend on them. The text lets the real
  wallet be used in any way, and the EasyCrypt experiment draws the record last.
- Fix by proof, in a new chapter `MhfeLean/Chapters/DeniabilityRecords.lean` (366 lines, 16
  declarations). No other chapter changed, except for the import line in `Checkpoint.lean`.
  - `Theorem2Records.prepared` is the prepared experiment with the record drawn last, from a kernel
    `Password → Entropy → Tables → State → Password → State → Record → PMF Record`: the real
    password, the entropy, the tables and the container, then the decoy password, the recovered
    decoy state and the disclosed record. The adversary, its budgets, the refusal flag, the
    arbitrary response after a refused first draw and the honest experiment are those of
    `Theorem2`.
  - `Theorem2Records.bound`, `.averaged_bound` and `.bits` state the bounds of `Theorem2.bound`,
    `.averaged_bound` and `.bits` for this experiment, unchanged:
    `(k + 2)·p1 + l/2^ENT + 12·(q + 12)/2^256 + 2/2^(2·width)`. `Theorem2.suite3_error` and
    `Theorem2.suite4_error` apply as before.
  - `Theorem2Records.disclosure_close` is the new step: on a run without the bad event the real
    record is never read, whatever its law, because `same_if_clean` holds for every value of the
    record. The other steps reuse `Theorem2.error_bound`, `Theorem2.prepared_flag_bound`,
    `Theorem2.new_eq_honest` and `Theorem2.honest_close`.
  - `Theorem2Records.independent`: the experiment of `Theorem2.bound` equals the new one with a
    kernel that ignores the container and the decoy. The former theorem is a case of the new one.
  - `RecordOrder.independent_agreement` and `RecordOrder.copied_agreement`: a Boolean record drawn
    before a fair disclosed record agrees with it with probability 1/2, whatever its law, and a
    record drawn after it can agree with probability 1. These are the audit's witness, stated for
    the two orders of drawing and not for two complete games.
- Still narrower than a literal reading of the text, and said so in the README: a record is fixed
  before the adversary runs, so a record that changes while the adversary queries is not modelled.
- Checked: `./check.sh` (below); `#print axioms` of `Theorem2Records.bound`, `.bits`,
  `.independent`, `.disclosure_close` and of the two `RecordOrder` lemmas gives `propext`,
  `Classical.choice`, `Quot.sound`; three negative controls (below).

### AUD-012-BLD001: the documented kernel-replay loop returned success when a replay failed

- Confirmed: the loop of the README ended every failed replay with `|| echo`, so its status was 0.
- Fix: `port-v4.35/check.sh` replaces the loop. It builds every module, requires exactly one
  inventory line of `Checkpoint.lean`, replays each chapter with `leanchecker` one at a time, and
  stops at the first failure with status 1 and the name of the step. It does not start (status 2)
  when `.lake/build` holds compiled modules of an earlier build, because Lake keeps a compiled
  module whose source is unchanged; it deletes nothing. The README describes the script.
- The replay names each chapter exactly. `leanchecker MhfeLean` would select every module below
  that name and replay them all at once; the entry file `MhfeLean.lean` only imports and declares
  nothing.
- Checked: `./check-selftest.sh`, five cases with a stand-in for `lake` (a failing build; a build
  without the inventory line; a module that the replay rejects, which must be named and must stop
  the replay; a leftover build; a run in which every step passes); the run on the 40 chapters
  (below).

### AUD-012-DOC001: the coverage claims lacked the remaining qualifications

- Confirmed.
- Fix by wording. The README no longer says that every result "is stated as a Lean theorem"
  without qualification. Its new section "Where the formal statements differ from the text" lists:
  - narrower than the text: total programs and their mixtures; finite passphrase alphabets in W5,
    W6, W7, the readings and the forms with private coins; the real wallet's record (FUN001); the
    forms with private coins that are not stated; the one-cost budget for general secrets; a
    generation that stops at a limit;
  - following from proved statements and not stated: the brackets after G8, K5 and W7 (with the
    `n + 1` candidates and the hypothesis of the `top2` forms of W7); the attainment of the
    fractional top, its lower bound and its form with `⌈x⌉`; `top2` as a ranked sum on a countable
    alphabet; the intermediate claims of G7; Theorem 5 with a selection rule as a parameter; the
    results on an unranked password alphabet other than Theorem 3;
  - read through an unchecked interpretation: phrases as groups of bits, with no word list, parser
    or SHA-256; the two oracle models; wallet records; the response after a refusal;
  - without a formal statement: the six-call remark, the estimates and examples.
  `MhfeLean/Chapters/README.md` says the same in short and points to that section.
- Not fixed by proof. Apart from the real wallet's record, every item above stands as the audit's
  table "Exactness limits" describes it.

### AUD-012-DOC002: the README described the native-evaluation axiom of an older Lean

- Confirmed in the pinned toolchain (`Lean/Meta/Native.lean`) and in the audit's control, where the
  checkpoint rejected `MhfeLean.AuditNative._native.native_decide.ax_1_1`.
- Fix: the README says that the checkpoint fails on any axiom other than the three, and that in
  Lean 4.35 each `native_decide` adds an axiom of its own named after its theorem, where earlier
  versions used `Lean.ofReduceBool`.

### AUD-011-DOC002, repeated for this development: "independently"

- Fix: the README says that the EasyCrypt development is separate, in another proof system, and
  that its author had read the statements of this development first. It says that the two give
  the same bounds under their own hypotheses and are not the same theorems.
