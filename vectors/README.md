# MHFE: Memory-Hard Feistel Encryption for BIP39 Mnemonics — published vectors

This directory belongs to the MHFE specification repository. It contains the
published deterministic public test data for `MHFE-BIP39-256-EXPERIMENTAL-2`,
generated by the separate `mhfe` Rust implementation repository. The JSON
files contain a public test password and round keys by design. Never substitute a
real recovery phrase or password.

The vectors are released under CC0-1.0. They provide positive interoperability
cases for zero-entropy 12-, 15-, 18-, 21-, and 24-word BIP39 sources, plus a
non-default-PIM case. Every
forward round was independently recalculated through a second Argon2id API.
Their reproduction does not establish cryptographic security or complete
negative and boundary coverage.
`SHA256SUMS` records the exact published JSON bytes.

| File                 | Source words | Recovery verifier |

| `zero-12-pim-0.json` |           12 |          128 bits |
| `zero-15-pim-0.json` |           15 |           96 bits |

## Fast verifier-serialization fixture

This small fixture checks verifier byte and bit order without running Argon2id:

```text
E224       = 000102030405060708090a0b0c0d0e0f101112131415161718191a1b
SHA256(E)  = dc27f8e8ee2d08a2bccbb2dbd6c8e07ffba194101fc3458c34ded55f72c0971a
V32        = dc27f8e8
CS7(E)     = 1101110
X256       = 000102030405060708090a0b0c0d0e0f101112131415161718191a1bdc27f8e8
```

`V32` is the first four digest bytes in their standard output order. `CS7(E)` is the seven
most-significant bits of the first byte, `0xdc`. Selecting the final digest bytes, reversing
`dc27f8e8`, reading bits least-significant-bit first, or using host-native integer byte order is
incorrect.
